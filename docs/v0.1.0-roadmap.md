# KeybChord Pico — v0.1.0 Roadmap

Reconstructed post-hoc record of the v0.1.0 development plan. This document is
the roadmap referenced throughout
[`KeybChord_Pico_Spec.md`](KeybChord_Pico_Spec.md) (as "Roadmap §5.2/§6/§8.2").
It records the milestone breakdown, the acceptance-criteria coverage matrix, and
resolves the three items the spec left open ("[DRAFT — REVIEW]"). v0.1.0 shipped
complete; this file is archived for reference. See
[`v0.2.0-roadmap.md`](v0.2.0-roadmap.md) for the current plan.

---

## 1. Milestones

Work proceeded in the order below; each milestone kept the native GoogleTest
suite green before it was considered done.

| # | Milestone | Status |

| M2 | Core framework — USB-host HID keyboard (TinyUSB + Pico-PIO-USB), State Manager, MIDI Router (DIN via `Serial2`/UART1), Config/Preset store (LittleFS + ArduinoJson), USB-CDC debug log + MIDI monitor | Done |

| M6 | Display — LCD idle screen (+ dirty `*`), parameter-edit feedback, prompts | Done |
| M7 | Presets/Config — JSON load/save, 80-slot navigation, save/clear with auto-cancel, per-function channels, defaults for uninitialized slots | Done |
| M8 | Polish — panic, latency/jitter tuning, robustness/hot-plug, config validation/fallback, full test suite | Done |
| M9 | USB Mass Storage + dev serial — FatFS backend, self-provisioning defaults in code, MSC bridge, boot-key composite mode | Done |
| M10 | Chord-engine upgrades + walking bass — chord roll, min notes, min-interval spread, manual inversions, arp modes, held extensions, walking-bass engine | Done |

## 3. Hardware pin map (resolves open item §14.1)

The canonical map, as validated during M1/M2 bring-up:

| Function | Pins |
|----------|------|
| Keyboard USB host (PIO-USB) | `GP0` = D+, `GP1` = D- (22 Ω series; `PIO_USB_DP_PIN_DEFAULT=0`) |
| DIN MIDI OUT (UART1) | `GP8` = TX (10 Ω to DIN pin 5; 33 Ω from 3V3 to pin 4) |
| LCD1602 + PCF8574 (I2C0) | `GP4` = SDA, `GP5` = SCL (3V3; auto-probe 0x27 → 0x3F) |

Source of truth lives in exactly two places — the `PIO_USB_DP_PIN_DEFAULT` build
flag and `keybchord/lib/hw/pins.h` — mirrored by `docs/wiring.md`.

## 4. LCD line-2 layout (resolves open item §14.2)

Shipped as the draft layout, data-sourced for future tuning:

```
Ebmaj7    *B1:P3
q=120  Rk  >Held
```

- Line 1: active chord + optional dirty `*` + bank/preset location.
- Line 2: tempo, 2-char rhythm short-code, play mode.

## 5. Rhythm list (resolves open item §14.3)

The 12 shipped patterns (indices 0–11), plus user-defined `/rhythms/*.json`:

`Rock 1`, `Rock 2`, `Waltz`, `Swing`, `Slow Rock`, `Bossa Nova`, `Rhumba`,
`Tango`, `March`, `Samba`, `Disco`, `Foxtrot`.

The 9 shipped bass patterns (`/bass/*.json`): `Walking`, `Whole`, `Half`,
`Quarter`, `Half Alt`, `Quarter Alt`, `3/4 Alt`, `Hold`, `No 6th`.

## 6. Persistence strategy (resolves open item §14.4)

JSON on FatFS-on-flash (512 KB filesystem partition), exposed to the PC as a USB
Mass Storage drive via the boot-key (`Ctrl` at power-on). Shipped rhythms/bass
patterns are embedded in code (see `keybchord/lib/core/defaults.cpp`) and
self-provisioned on first boot rather than shipped as a LittleFS image.
Large static tables are not compiled into flash; everything user-editable is
JSON on the drive.

## 7. Shipping

v0.1.0 shipped the firmware (`firmware.uf2`, built by
`.github/workflows/release.yml`) together with the cross-platform
**KeybChord Configurator** GUI (`configurator/`, built for Windows/macOS/Linux
by `.github/workflows/configurator.yml`).
